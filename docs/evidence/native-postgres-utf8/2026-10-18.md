## Cause and bounded fix

The native community, isolation and replay launchers previously omitted initdb's
encoding argument. With the inherited C locale, PostgreSQL 17/libc initializes a
SQL_ASCII database. The unchanged 500 `界` fixture occupies 1,500 bytes and is counted
as 1,500 characters there, failing the existing `varchar(500)` column with SQLSTATE 22001. The same workload succeeds in the Docker UTF-8 environment.

All three native launchers now pass `--encoding=UTF8`, preserving locale, SCRAM
credentials, loopback ports, modes, process sequencing and cleanup. No application,
applied migration, column limit, npm dependency, stress fixture or workload assertion changes.
Isolation/replay runs verify and report their actual connection encodings and native
C locale. The community check verifies server/client UTF8, locale/collation, character
and byte lengths, the existing column's 500-character bound and exact runtime-role
INSERT/SELECT readback; its transaction rolls back before the other fixtures.

`npm run verify:community-native-setup` builds and runs the existing community harness
with `--setup-only` under `LC_ALL=C LANG=C COMMUNITY_POSTGRES_MODE=host`. This requires
native PostgreSQL 17/18 and uses the same initdb/provision/migrate/cleanup path, stopping
before browser/load work. The existing required `integration` job installs native
PostgreSQL 17 from the runner's configured PGDG repository, adds its binaries to PATH,
and invokes this smoke check. Existing five CI names and all other gates remain.
The official [runner repository inventory](https://github.com/actions/runner-images/blob/main/README.md)
and [PostgreSQL Ubuntu instructions](https://www.postgresql.org/download/linux/ubuntu/)
describe that package source. No new GitHub Actions dependency is added.

## Regression and cleanup proof

The focused smoke runs the actual native setup. Separate fresh-cluster negative
controls temporarily copy the source alongside its relative imports, either remove
only the UTF-8 initdb argument or set the probe's actual client connection encoding to
SQL_ASCII. They fail with the explicit corresponding prerequisite diagnostic before
browser/load phases. Original maintained source hashes remain unchanged.
Native command wrappers record successful initdb/start/stop calls and the postmaster
PID. Success and both failures must remove the temporary cluster directory and leave
the recorded postmaster exited. No forced cleanup replaces the harness's finally path.
An initial attempt to set client encoding through startup options was overridden by
the driver; the accepted negative control changes the actual session setting instead.
An initial smoke query incorrectly treated locale as a GUC; it failed, cleaned up,
and was corrected to read `pg_database.datctype/datcollate` before accepted runs.

The temporary control driver was invoked with the same Node/PostgreSQL PATH:

```sh
node /private/tmp/yaparena-native-utf8-cleanup-proof.mjs
```

It is a one-off verification driver, not a new repository tool. The maintained
regression protection is the npm command and native CI step above.
[Its sanitized cleanup report](cleanup-proof.json) records three fresh native clusters:
successful UTF8 readback exits 0; omission of `--encoding=UTF8` observes SQL_ASCII,
1,500 characters/1,500 bytes and exits 1; an actual `SET client_encoding = SQL_ASCII`
on the probe connection exits 1. The failures identify the encoding prerequisite
before browser/load execution. All three record a successful normal cluster stop,
removed cluster/parent directory and exited postmaster. Temporary source copies and
wrappers were removed, and the maintained source hash was unchanged. No cleanup
failure was suppressed to obtain these results.
