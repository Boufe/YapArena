## Cause and bounded change

PR #36's [post-merge integration failure](https://github.com/Boufe/YapArena/actions/runs/39162521429/job/117778917866)
timed out waiting for the inline commitment form. Its source tree matches the
successful PR revision exactly. The inline page revealed participation controls
after authentication, before publication/run/workspace initialization finished.
The existing busy guard ignored the verifier's early creation click.

`frontend/a4-inline.ts` now marks the participation panel busy and disables its
form controls during that initial action. A finalizer runs after `act()` releases
its guard, restores each control's original disabled state and clears the busy
attribute. Existing error handling still runs; controls are restored on failure
as well as success. Later actions, timers, requests, validation, authorization,
economic rules, database operations and media/chat nodes are unchanged.

`scripts/verify-a4-browser.ts` holds the actual initial workspace request in the
disposable runtime. It verifies the intermediate disabled state, releases the
request in `finally`, waits for readiness, and uses one ordinary click. It asserts
one creation request, one stored run, one open round and a visible commitment
form before continuing all prior scenarios. Only the owner-side test probe reads
the database; the application still receives runtime credentials only.

No dependency, package command, migration, production setting, timeout, retry,
forced click, arbitrary sleep, fixture outcome or existing assertion changes.
Both files remain in their existing strict compiler projects and the existing
required integration job invokes the regression through the browser gate.
